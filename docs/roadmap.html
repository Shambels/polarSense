Part 01

Planned, not built

Scoped in the build plan, cut to get a working extension out. Nothing here needs a design decision — the shape is already settled.

Object storage: s3:// and gs:// plan M6 · src/storage/

The one you said was real. Storage already abstracts stat/readAll/list/asyncBuffer, and hyparquet only ever asks for byte ranges — so S3 is GetObject with a Range header plus ListObjectsV2, and the credential chain comes free from @aws-sdk/client-s3. Needs ETag-keyed caching, a persistent globalStorage cache, and per-scheme opt-in so completions never issue billable calls unasked.

needs a decisionimpact high2 d

Delta checkpoint fallback shipped plan M5b · src/schema/delta.ts

Through the hyparquet path already in the repo, as planned. It runs second on purpose — a JSON commit is always newer than the checkpoint beneath it, so the walk keeps the last word and a stale checkpoint can never surface. The checkpoint is chosen from the directory listing already in hand rather than from _last_checkpoint, which can be missing or stale without the checkpoints themselves being either.

A checkpoint of a million files still decodes a handful of rows: the row group holding the metaData action is located from the footer's own null counts — the same statistics hover already reads — so the read is targeted rather than a scan. Without statistics it reads the head of the file, where every writer puts protocol and metaData.

One thing the estimate did not see coming. This is the only place the extension decompresses a parquet page rather than reading a footer, so it is the only place the compression codec matters. Snappy, which Spark and delta-rs write, worked from the start; ZSTD reported nothing, on the grounds that a third dependency to decode it was not worth it for this one path. Value completion changed that arithmetic — it needed zstd or it did nothing at all — so fzstd arrived and this reader got it too. Brotli and LZ4 still report nothing.

0.5 d

Arrow IPC / Feather shipped src/schema/ipc.ts · dtypes.ts

The hand-rolled flatbuffer walk this entry called for, in its own file rather than tacked onto the parquet reader. Names, dtypes and a struct's own fields, in two range reads and no decompression — the cost does not move with the size of the file. read_ipc_stream joined the reader table on the way past, since the stream shape now reads.

Where the plan was wrong: the schema is not dependably at the head of a file. It is in a stream, and that is where a stream is read. But polars writes a file's first message with no length prefix in front of it, so a reader scanning forward from the magic walks straight off the end — the fixture proved it before the tests did. A file is read through its footer instead, the index its own spec puts there, which also makes the read authoritative rather than a guess about writer behaviour.

The dtype work was the half the estimate didn't see. Polars writes view types — Utf8View, BinaryView — and large lists, none of which the parquet corpus exercises, so the fixture had to be built around what polars emits today rather than what Arrow documents. A dictionary-encoded string is cat: the encoding is the difference. Interval and union get a blank dtype, on the usual grounds.

Part 02

Deliberate limitations worth revisiting

Traded away on purpose for a single-file, no-propagation v1. Each is asserted as a passing test, so fixing one is a visible change rather than a silent drift.

Schema propagation shipped src/core/frame.ts · schemaEval.ts

A frame is now its source plus the transforms applied to it. select, with_columns, drop, rename, with_row_index, group_by+agg and join are all modelled; anything else keeps the columns it had and clears a certain flag rather than narrowing wrongly. This was the correctness ceiling for everything else, and clearing it is what made diagnostics safe to ship.

3–4 d

Cross-module frames shipped src/core/modules.ts · src/modules.ts

Not the workspace-wide index this entry called for. Only the modules the open file actually imports are read, two hops out and capped at sixteen files, each parse cached until its mtime changes — demand-driven, so a large repository costs nothing until you import something from it. The names an import brings into scope became part of the binding table, and a name it cannot answer for is handed to the table of the module it came from.

The piece that made it worth doing is that a definition travels with the module it belongs to: a chain built in loaders.py keeps its transforms, and that file's own path constants fold in that file. Falling back to "the source, minus everything done to it" would have offered columns that no longer exist.

Function returns came along with it — def load(): return pl.scan_parquet(…) now resolves whether the def is imported or in the file you are editing. Module-level defs only; a method needs an instance this analysis cannot follow.

2 d

The pragma escape hatch shipped src/core/pragma.ts

Designed in the plan, dropped from v1, and now the answer for the one frame this cannot read: a path arriving as a function parameter, a config attribute or an environment variable.

# polarsense: data/sales.parquet
return pl.scan_parquet(cfg.source_path)

def report(df):  # polarsense: data/sales.parquet

It governs the statement it is attached to, and on a def it answers for that function's parameters. Two decisions did most of the work. It is consulted last — a path the code can supply always wins, so a pragma left behind after the code was fixed cannot start lying about a frame that is now readable. And where the reader call is right there and only the path would not fold, that call keeps deciding the format and its options; the comment supplies the path and nothing else.

Named polarsense: rather than the plan's polars-schema:, because by the time it was built the extension was no longer polars-only. Half a day, as estimated — the resolver interface it had been designed behind was still there.

0.5 d

df["…"] and get_column shipped src/core/resolve.ts · triggerSites.ts

One branch in findArgumentPosition for subscripts, one table row each for get_column, get_column_index and drop_in_place. The catch was that a dict lookup has the same syntax tree as a frame one, so the receiver decides: cfg["path"] offers nothing at all rather than falling back to every schema in the file.

1 h

Nested struct fields shipped src/schema/parquet.ts · core/resolve.ts

The tree is kept rather than discarded, and not only in parquet — Delta's schemaString and Iceberg's metadata nest the same way, so all three recurse. A Column can now carry its own columns, which is the whole feature: the rest is a path — ["address", "geo"] — carried on the resolution, and one walk down it before the columns are offered.

Because the site produces an ordinary resolution and range, hover and the unknown-column check followed without asking: .struct.field("citt") warns and offers city. A path the schema cannot follow returns null rather than an empty list, so "no idea" stays distinguishable from "this struct has no fields" and the diagnostic stays quiet.

The perf guard earned its place here. Keeping the tree meant asking every node whether it is a struct, which cost a 5000-column file about 10%; the guard flagged it, and reordering the check to look at the child count first made a flat file faster than before. Two smaller finds came with it: a struct field can have its own statistics, since the footer keys them by full path, and .struct.field("city") had been propagating downstream under the name of the struct rather than the field.

1 d

sheet_name= in read_excel shipped src/schema/excel.ts · core/bindings.ts

Both halves, as scoped. sheet_name and sheet_id joined KEPT_KWARGS so the argument survives the call site at all — without that entry the reader is never told, and every reader test passes anyway, which is why the corpus case for it lives in resolver.test.mjs rather than beside the reader. Then xl/workbook.xml gives the tabs in tab order with a relationship id each, and xl/_rels/workbook.xml.rels says which part an id lives in.

The dialect split was the one thing the entry did not mention. polars spells the position sheet_id and counts from one; pandas overloads sheet_name, where a number is a position counted from zero. Both reach the same reader, so both are understood — three lines, and without them pd.read_excel(…, sheet_name=1) would have looked for a tab named "1".

What made it worth more than the convenience: the default moved too. Asking for nothing now means the first tab rather than the part called sheet1.xml, and the fixture pins the difference — a workbook whose first tab is stored in sheet3.xml, which the old reader would have answered wrongly and silently.

The fallback went the other way from the plan. There is no longer a "if the workbook cannot be read, use sheet1.xml" branch: a sheet asked for by name and not found, or a workbook with no readable parts list, now reports nothing. Guessing a part name was the one place this reader could be confidently wrong rather than quiet, which is not the trade the rest of the extension makes.

Glob schema union, and hive dtypes

Two small honesty gaps. A multi-file glob reads the first match and assumes the rest agree; a heterogeneous set silently shows the wrong columns. And hive partition columns are always reported as str, where polars infers i64 for year=2026.

Part 03

Not in the plan, worth adding

Ideas the build plan never considered, mostly because v1 was scoped to completion alone. Most of these are now built.

Complete the file path itself shipped src/paths.ts

Typing inside pl.scan_parquet("da…") offers matching files and folders, filtered to the formats that reader can open. Folders re-trigger the suggestion list; table readers offer only directories, and mark the real tables.

0.5 d

Diagnostics for unknown columns shipped src/diagnostics.ts

A warning on pl.col("regoin") with a quick fix offering "region". Reports only where the schema evaluator says certain; an unmodelled reshape, a selector it cannot narrow, an unidentified frame, an unreadable file or a truncated schema all mean silence. Twelve of its nineteen tests assert that it says nothing.

1 d

Hover with column statistics shipped src/hover.ts

Dtype, null count, min and max — all from the parquet footer already read for the schema, so no extra I/O. Dates and timestamps are formatted rather than shown as epoch integers. Hovering a path shows the file it resolves to and its shape.

1 d

Value completion shipped src/schema/values.ts · core/resolve.ts · core/triggerSites.ts

The showpiece, and off until polarsense.values.enable says otherwise. == "…", !=, .is_in([…]), .eq/.ne, and the right-hand side of a constraint keyword — which is the same position whose left-hand side has always completed column names.

The string namespace joined them afterwards: .str.contains, .starts_with, .ends_with, .contains_any, .str.find and .list.contains. Cheaper than it looks — the value table is keyed by method name like every other trigger row, and .str was already a namespace the name walk passes through, so the whole feature is one longer set. The receiver doing the deciding is also what keeps cs.contains("reg") intact: same method name, opposite meaning, and cs names no column, so that site still completes column names as a fragment.

Where it is knowingly generous rather than certain: contains matches a regex unless literal=True, so a value holding . or ( is offered as a pattern that means something else once inserted. Nothing escapes it and nothing checks it — a value site is never typo-checked — and the alternative was silence in the position people reach for most.

Not dictionary pages. hyparquet does not expose them, and it turned out not to matter: reading the first values.maxRows rows of one column is one column chunk either way, and on a dictionary-encoded column that is the dictionary page plus a run of indices into it. What the entry called low-cardinality became a rule instead of a hope — past values.maxDistinct the answer is nothing, not a truncated list, and a column whose values are not strings gets the same silence, because a value site is always inside quotes.

The thing the estimate missed: polars writes parquet with zstd, and hyparquet decodes snappy. Without a decompressor the showpiece would have done nothing on a file polars had just written — so fzstd is a third runtime dependency now, and the Delta checkpoint reader, the only other place a page rather than a footer is decompressed, stopped being zstd-blind as a side effect.

Free and exact in one case: hive partition columns. The directory names are the domain, so no data is read and the list can never be a sample — everywhere else, a read that did not cover every row says value (sampled) on the item itself.

impact high2 d

Ctrl-click a path to open the file shipped src/links.ts

A DocumentLinkProvider over the resolved path. Constants link too, and a glob or directory names the concrete file it resolved to in the tooltip.

2 h

polars.selectors shipped src/core/selectors.ts

The trigger table gained the name-taking selectors and the alias forms — import polars.selectors as cs, from polars import selectors as cs, from polars.selectors import by_name. The half that pays, though, is the other one: a selector is now a predicate over the frame's own columns, so cs.numeric(), cs.starts_with("q_") and cs.matches("^re") narrow instead of surrendering, and |, &, -, ^ compose them as polars does. One fewer reason for the diagnostic to go quiet.

Two places it still says nothing, on purpose. A dtype selector over a source whose dtypes were never read — a CSV with inference off — cannot be resolved without inventing types. And cs.starts_with("reg") holds a fragment of a name: completion still offers whole column names there, but the typo check skips it, because "reg" was never meant to be one.

0.5 d

Constraint keywords shipped src/core/resolve.ts

Exactly as predicted: a different trigger path, and past it nothing new at all. One branch before the string check walks from the cursor to an argument_list whose call takes constraints, and hands back the same shape every other site produces — same frame, same schema, same narrowing through whatever transforms came before. The name is inserted with its =, since nothing else would be valid there.

Typo-checking and hover came along without being asked for. Both already work from a resolution and a range, and this produces both, so df.filter(regoin="EU") warns with the same one-click fix as everywhere else.

1 d

Columns inside SQL strings shipped src/core/sql.ts

The light scan this entry asked for, and no more: literals and comments are masked out, then whatever follows FROM and JOIN is a table. A reference resolves four ways in order — a quoted path or reader call is a file, self is the receiver, a name registered with SQLContext is that frame, and anything else is looked up as a plain Python name, which is what makes pl.sql("SELECT * FROM df") work at all.

Where the scan stops is the interesting part. Every table is in scope everywhere in the statement, so a subquery's tables leak outward and a join offers the union of both sides — returned as a join with no keys, which marks it uncertain, because which side a bare name belongs to is genuinely unknown. An alias narrows it: SELECT s.… offers only s's columns. And a SQL position is never typo-checked, since the scan cannot tell a column from an alias or a function.

It also paid for a bug. A completion used to replace the whole string, which was invisible while every site held one name and wrong the moment one held several — rel.project("region, reve") would swallow the first name. Every fragment site now narrows to the identifier under the cursor, which incidentally made hover work inside them.

2 d

pandas and duckdb shipped src/core/triggerSites.ts · sql.ts · frame.ts

The bet in this entry paid: the trigger table got longer and almost nothing else changed. Rows are keyed by method name and the receiver still has to resolve to a file, so groupby and sort_values cost nothing in a polars file — no dialect detection, no second resolver. Propagation needed real work only where pandas differs in kind: df[["a","b"]] is a select written as a subscript, and merge suffixes collisions _y where polars says _right.

duckdb needed one new idea. Its path lives inside a string — duckdb.sql("SELECT * FROM 'sales.parquet'") — so core/sql.ts looks for a reader call or a quoted path with a known extension and finds nothing otherwise, which is what keeps execute("SELECT * FROM users") quiet. The relational API's arguments are SQL fragments rather than names, so they complete and are never typo-checked, reusing the marker cs.starts_with introduced.

pyarrow was left out. Its read_table means parquet where pandas' means CSV, and telling them apart needs the module the call came from — the one place where a dialect really would have to be detected.

1–2 d

NDJSON, JSON and Excel shipped src/schema/json.ts · excel.ts

Where the entry was wrong: this is two readers, not three. The shapes polars accepts — an array of row objects, newline-delimited objects, a single object — are all top-level {…} runs in order, so none of them has to be told apart from the others. One brace-depth scanner that ignores braces inside strings reads all three, over the same bounded prefix csv.sniffBytes already governs, and an object the read cut in half is dropped rather than ending the scan.

"The first line" and "the first object" were both wrong too, in the same way the glob entry is wrong. polars unions keys across rows, so this samples fifty: a key absent from row one is still a column, and the first row holding a non-null value for a key is what decides its dtype. A key that is null throughout gets a blank, which is the CSV inference default arriving at the same answer by the same reasoning. Nested objects keep their fields, so .struct.field("…") answers for them as it does for parquet.

Excel cost no dependency, which the estimate did not expect. .xlsx is a zip of XML and node's inflateRawSync decodes the one method a spreadsheet writer ever uses, so the header row is a central-directory read and two regexes — central directory, not a scan of local headers, because a streamed member writes its size after the data rather than in front of it. The detail worth having is that a skipped cell is named rather than closed up: Excel omits an empty cell entirely, and closing the gap would shift every column after it under its neighbour's name.

Still not done: sheet_name=. It reads sheet1.xml, which is what polars, pandas and Excel all write first, and mapping a name to a sheet means workbook.xml plus its relationships — additive, and not worth it until someone asks. .xls is OLE2 wearing a similar extension and reports nothing.

1 d

Warm the cache on open shipped src/warm.ts

Made deliberate, as this entry said was all that was left. The difference from the side effect it replaces: it happens with the unknown-column check turned off, on open rather than a pause after the first edit, and for every source the file names rather than only the ones sitting at a column position — which since cross-module frames includes a frame imported from another module, because that is one of the importing file's own sources too.

Re-warming is cheap rather than tracked. The parse is cached and a schema already read is a cache hit, so it runs on every open and every editor switch with no bookkeeping to remember what it has done — the one piece of state it would have needed is the one piece that could go stale.

No test of its own: it needs an editor. What it leans on — that an imported frame is one of the importing file's sources — is pinned in the module corpus instead.

2 h

A "show schema" command shipped src/showSchema.ts

The status item is a link now: clicking 24 cols lists the columns with the dtype, min, max and null count the schema read had already paid for, and picking one writes it at the cursor — replacing the half-typed name if you were in the middle of one.

One thing this entry did not anticipate: invoked from the command palette, the cursor is usually nowhere near a frame. So it falls back to the sources the file reads — straight in if there is one, a pick between them if there are several — which is the difference between a command that works and one that only works if you are already standing in the right place.

Part 04

What I'd do next

Published, the audience is no longer polars-only, and every frame the resolver cannot see now has either a way in or a way to be told. The one that had been last on purpose since the beginning has shipped, which leaves a single item — and it is not waiting on work, it is waiting on an answer from you.

What changed in the ordering

Schema propagation was the constraint, and it has landed — so nothing on this list blocks anything else any more. Value completion has landed too, which is the one that changes what feedback is worth: it is the first feature here that is off by default, so how many people turn it on says more than any estimate above ever could. One week of real usage on real files should be allowed to reorder what is left.

Still not on this list

Rewriting the analysis to consume a real Python type checker's output — Pylance's or pyright's — instead of the hand-rolled binding table. The case for it was that it would solve cross-module frames and propagation at once; both are now solved without it, which leaves very little. And pyright still has no plugin interface for contributing string-literal completions. Worth knowing the door exists; still not worth walking through.
